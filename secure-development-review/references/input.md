# 入力と処理境界

## INPUT-1 — データと命令を混同しない
守る条件: 構文・意味・範囲を検証し、使う先に合う保護を適用する。
証拠: 入力元からSQL・コマンド・テンプレート・ブラウザ等への経路、パラメーター化、文脈に合うエンコード、構文解析の設定。入力検証だけで命令注入の対策済みとしない。

## INPUT-2 — ファイル・形式・オブジェクトの境界
守る条件: 意図した領域と能力だけで処理する。
証拠: 保存先・展開先、正規化と親移動・絶対パス・リンク、形式解釈やデシリアライズによる機能、アップロード後の配信方法。名前・拡張子・申告Content-Typeだけを信用しない。容量等はSTATE-2も選ぶ。

## INPUT-3 — 外部通信の接続先と能力
守る条件: 利用者入力から意図しない内部資源・資格付き通信へ到達させない。
証拠: URL解析、許可する宛先、名前解決、リダイレクト、共通クライアントが付ける資格情報、ネットワーク制限、応答の時間・容量。実際の構成に応じてアプリと環境の保護を合わせて判断する。

拡大: ラッパー・パーサー・共通クライアント・取得したデータの再利用先が変わる場合、その経路まで追う。
終了: 関係する入力が到達する処理先と保護が分かる。未提示の隔離・制限は仮定しない。
出典: ASVS 5.0.0 V1/V2.2/V3/V4/V5/V13.2、OWASP Input Validation/File Upload/SSRF Prevention、IPA『安全なウェブサイトの作り方』改訂第7版第4刷の第1章1.1/1.2/1.3/1.5。分類・選別・終了条件はこのスキルの設計。各原典の全要件を採用したものではない。

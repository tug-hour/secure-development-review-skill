# 状態・並行処理・資源

## STATE-1 — 業務上の不変条件
守る条件: 順序、部分失敗、再試行、並行実行でも、数量・権利・残高等の条件が破れない。
証拠: 状態遷移、確認と更新の原子性、トランザクション境界、条件付き更新・制約、冪等性。データ競合がなくても、分離された確認と操作で業務上の競合が生じ得る。

## STATE-2 — 消費と終了の制御
守る条件: 到達可能な操作で、意図した時間・容量・数・並行度を超えて消費させない。
証拠: 入出力・展開・検索・正規表現・キュー等の負荷、タイムアウト・キャンセル・再試行、エラー時の解放、負荷制限の適用単位。形式が正しい入力にも上限を考える。

## STATE-3 — 数値・メモリ・実行条件
守る条件: 境界値、変換、寿命、共有、ビルド条件の違いで安全性の前提を壊さない。
証拠: 数量・長さ・金額の演算と比較、オーバーフローや切詰め、メモリ・FFI・危険操作の前提と隔離、エラーからの復帰。具体的な保証は使用言語・版・設定で確認し、C固有の禁止を他言語へ転用しない。

拡大: 共通の資源管理、ロック、数値変換、再試行方針が変わる場合、その利用先と失敗経路まで確認する。
終了: 関係する状態と負荷の条件、失敗時の挙動が分かる。既存のテスト・fuzzing・race検査は実行した範囲の証拠として使う。
出典: ASVS V2.3/V15.4、CERTの数値・エラー・並行処理、ANSSI Rust、Go Security、OWASP DoS。分類・選別・終了条件はこのスキルの設計。

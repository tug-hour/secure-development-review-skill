# 検査観点の選別索引

各行を「今回どの安全性の条件が変わるか」だけ確認し、詳細は選んだ分野だけ読む。SQL・ログ・暗号等が存在するだけでその分野を追加しない。条件と経路が変わらず適用できる証拠がある部分は再利用する。分野名は検査範囲を整理するためのもので、報告の必須見出しではない。

| ID / 分野 | 選ぶ条件 | 詳細 |
|---|---|---|
| identity | 主体、認証、セッション、操作・対象データ・フィールド・テナントの許可、信頼するIDの出所が変わる | [認証・認可](identity.md) |
| input | 入力をSQL・コマンド・テンプレート・ブラウザ・デシリアライズ・ファイル・外部通信に渡す経路、またはその保護が変わる | [入力と処理境界](input.md) |
| data | 収集・保存・返却・ログ・エラー・一時領域・成果物・通信のデータ、暗号・鍵・秘密情報の扱いが変わる | [データ保護](data.md) |
| state | 状態遷移、順序、再試行、共有資源、並行処理、容量・時間・数値・メモリの前提が変わる | [状態と資源](state.md) |
| supply | 依存・ツール・取得元・ビルド・CI・権限・配布・実行設定が変わる、または関係する新しい脆弱性情報がある | [依存と実行環境](supply.md) |

例: 推移的依存の展開処理に問題があり、入力が到達するならsupplyとinputを選ぶ。ログ項目の追加ならdataを選び、その値が認証・認可へ影響するときidentityも選ぶ。

関連がないことを実装・構成・仕様から確認できれば対象外にする。索引に当てはまらないが安全性への影響が考えられる変更は、最も近い分野と不足する観点を明示して確認する。資料不足を非該当に変換しない。

# Goに関係する評価基準

Goコード/バイナリ、toolchain、依存、検査/是正に具体的な疑問がある場合に必要な節を使う。全6条件や全系統の適用判定を要求しない。推奨・任意と実行範囲の限界を保つ。

出典: The Go Authors, [Security Best Practices for Go Developers](https://go.dev/doc/security/best-practices)。2026-11-01に公式本文を新規取得・読解し、6節すべてを以下へ対応付けた。旧スキルの条件文・分類・採否は流用していない。原典の助言を日本語のレビュー条件へ再構成し、推奨を一律の義務や欠陥判定に変えない。

| 参照 | 適用・強さ | 確認する条件と根拠 |
|---|---|---|
| GO-VULN | Goコード/バイナリと依存。推奨 | 定期的な脆弱性確認と対象への影響判断を確認する。govulncheckの定義だけでなく対象版・実施範囲・結果・未是正を見る。エディター/CI連携やJSON出力は手段の例で、特定製品を必須にしない |
| GO-UPDATES | Goと外部依存。推奨 | 実使用Go版の更新・セキュリティ修正と、最新minor版への追従を確認する。外部依存は更新を吟味し検査する。最新版番号だけで安全とせず、互換性・新しい不具合・悪意ある変更の影響も確認する |
| GO-FUZZ | 入力を扱うコードと検査。推奨 | 通常例では届きにくい境界をfuzzingで確認する能力と、対象/実績を見る。検査の存在を全経路の成功や脆弱性不存在としない |
| GO-RACE | 共有値を並行利用するコード。推奨 | 並行アクセスと書込みの有無、race detectorの対象/結果を確認する。検出は実行した経路の動的競合に限られ、未実行経路まで安全とはしない |
| GO-VET | Goの静的検査。推奨 | vetによる疑わしい構造の検査範囲/結果を確認する。実行定義やコンパイル成功だけで検査済みとせず、安全性全体の保証にも使わない |
| GO-NOTIFY | Go安全修正の情報取得。任意の手段 | golang-announceの利用は情報取得手段の例として扱う。購読自体を必須にせず、未購読だけで欠陥としない。購読・登録を自動実行しない |

原典節との対応は順に、脆弱性スキャン、版/依存更新、fuzzing、race detector、vet、セキュリティリリース通知。具体的な最新版・既知脆弱性・各ツールの現在の詳細仕様は、レビュー時の対象と必要性に応じて一次資料で確認する。インストールや検査実行をこの文書だけで許可しない。

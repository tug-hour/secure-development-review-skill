# 評価基準の案内

具体的な技術・経路・規範条件が判断を左右するとき、関係する資料の必要部分だけを読む。全系統の適用確認や全IDの判定を先行工程にしない。共通根拠は再利用し、原典の前提・数値・例外・強さを保つ。下表は参照先を選ぶ案内であり、順番に埋めるチェックリストではない。

| 基準 | 適用と読む範囲 |
|---|---|
| [ASVS](asvs.md) | アプリ/サービス/クライアントの入力、認証/認可、データ、通信、設定、依存、ログ等。各機能がなければ理由を持って節を非適用にできるが、Web用という名称だけで共通の保護まで除外しない。指定水準と実際の保護対象を区別する |
| [OWASP Cheat Sheets](owasp.md) | 認可、入力、upload、SSRF、ログ、HTTP、DoS、供給網、レビュー、攻撃面。入口/外部通信の有無と、依存/CI/変更の役割へ照合。原典記事間の重複は共通根拠で扱い、説明用コードや製品例を一律義務にしない |
| [IPA](ipa.md) | Web/HTTPに関わる入力・出力・認証/セッション等。根本対策と保険的対策、代替を区別する。保険的対策だけで主要な防御を満たしたとしない |
| [CERT C](cert-c.md) | Cコード/C互換FFIと実行環境に応じた規則/推奨。C固有のAPIや型を他言語へ強制しない。共有/寿命/境界などの共通リスクは他の適用基準と結び付ける。原典未完成/廃止/版依存を確定要求と混同しない |
| [SSDF](ssdf.md) | 対象の開発・保護・実装検査・取得/配布・更新是正。組織側の証拠が必要な条件をコードだけで満たしたとしない。実装例を義務化せず、今回レビューの実施を製品工程全体の充足へ置換しない |
| [ANSSI Rust](rust.md) | Rust実装、toolchain/build、依存、unsafe/FFI/APIの前提。Rust固有の条件は言語/環境を確認して適用。Rule/Recommendationのラベルだけでなく本文のMUST/推奨/高保証条件を読む |
| [Go](go.md) | Goの実使用版と依存、脆弱性確認、fuzz/race/vet、修正情報の取得。推奨/任意、実行した経路に限る検査能力を保持し、他言語へ特定ツールを要求しない |

対象自身・基盤・利用側・運用の責務を分ける。対象コードに機能がないことを理由にできる非適用と、未提供の構成/運用で適用が分からない未確認を区別する。重要な判断に必要な対象内の不足は、外部証拠不足と分けて調べる。

原典の固定範囲・取得点・権利条件は[sources.md](sources.md)。これは基準の保守/解釈が必要なときに参照する資料で、毎回全量を読む必要はない。原典の未確定事項・新規実装の残る制約は各基準の明示を引き継ぐ。

案内の変更: 2026-11-03、全件評価の手順から必要時参照へ変更。原典の具体条件・帰属・許諾は保持。

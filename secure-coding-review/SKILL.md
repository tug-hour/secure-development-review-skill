# セキュアコーディングレビュー

対象の保護対象・信頼境界・権限・データと状態の流れを把握し、セキュアコーディング/開発ガイドの知見を使って重要なセキュリティリスクをレビューする。調査対象・順序・深さは、実装・設計・設定・依存と利用条件から選ぶ。

重要度に応じて調査の深さ・対応優先度・説明量を調整する。重要な影響が疑われる不足へ優先して根拠を集め、軽微な問題は必要な確認と簡潔な報告で扱う。元のレビューで気付いた有効な機能・契約・状態の問題も保持する。

入力と利用先の解釈、認証・認可・token、業務と共有状態、データ・暗号・通信、ファイル/外部接続、メモリ・型/言語境界、資源と失敗処理、構成・監査、供給網・継続是正を判断の足場にする。これは全件判定のリストではなく、対象に応じて具体的な攻撃経路や保護の破綻を考える観点である。

正常系だけでなく、拒否・例外・部分失敗・再試行や、層/設定の組合せで保護が崩れないかを考える。共有状態では、更新と利用が重なる場合の競合と、組として必要な状態の一貫性を考える。特に失敗・未設定・代替を表す値が、後続で正常な選択肢として受け入れられ、必要な保護を失ったまま処理が成功しないかを追う。任意機能の無効化やfallback自体を欠陥とせず、利用条件に応じて必要な保護と成立する影響を示す。認可は代理サービス越しの主体や権限変更後も、入力/宛先の検証は実際の利用・接続まで結び付ける。利用側・外部基盤へ委譲した保護は、対象自身の保証と分ける。更新・回帰検査・脆弱性対応を通じ、安全性を維持/回復できるかも対象に関係する範囲で見る。検査・方針・設定が存在するだけで、実効性や安全な結果を確認済みにしない。

既存の根拠・所見は対象の版・設定・利用前提と確認範囲が今回の問いにも有効な場合に再利用し、重要な判断に足りない証拠だけを同じ経路・設定ごとにまとめて調べる。行番号など報告に必要な情報も可能なら最初の取得に含め、再取得は前提変更・出力の欠落・重要な問いへの証拠不足がある場合に絞る。取得しただけで評価済みとせず、結論を根拠へ結び付ける。

リスクは影響範囲・成立条件・既存防御で判断する。条件付きというだけで軽くせず、不明な前提を最悪の事実として扱わない。ガイドの要求水準や必須/推奨を重大度へ変換しない。確認の価値は、重要なリスク/保護・誤認・必要な対応や証拠が何か明らかになったかで捉える。

重要な所見と未確認を先に示し、箇所・根拠・成立条件・影響・対応を簡潔に報告する。実際に扱った範囲を示し、重要な結論に関係する既存防御も伝える。有効な既存/追加所見を落とさず、訂正・統合・除外には理由を持つ。軽微な問題は補足へ集約し、同じ制約や責務を繰り返さない。

## 必要な参照と終了

具体的な規範・数値・技術固有の動作・例外・推奨の妥当性が結論や対策を左右するとき、[参照案内](references/criteria.md)から必要部分へ進む。疑問だけでなく対象の技術・委譲境界・失敗経路も参照先を選ぶ手掛かりにする。資料は判断の知識源であり、全IDの判定・全系統の非適用説明・適合率は要求しない。参照先に残る旧方式の全件評価・全採用条件の判定手順は適用せず、本本文の必要時参照を優先する。原典の前提・例外・数値・強さを保つ。

主要な攻撃経路・保護・変更影響と、見つかった具体的な重要疑問に必要な調査が終わったら報告する。重要な所見に関係する保護の責任境界と、その問題を継続して防止・検出・是正できる根拠または不足を、所見や結論に簡潔に結び付ける。未解決なら問い・必要証拠・制約を明示する。未読資料だけを理由に調査を広げず、重要な判断を変え得る具体的な不足は放置しない。全要求への適合や欠陥不存在は保証しない。ガイドの導入・実行例は操作承認ではない。
